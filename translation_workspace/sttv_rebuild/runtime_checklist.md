## 3-1. 발견 이슈 R01 — ASCII 문장부호 글리프 미등록

- 상태: **첫 대사 PPSSPP 재검증 PASS / 나머지 문장부호 검증 진행 중**
- 최초 재현: 개발 메뉴 첫 대사 `이봐! / 찾았다!`
- 실제 출력: `이봐 / 찾았다`
- 판정: `GLYPH_BAD`
- 저장 데이터 확인:
  - `이봐!`: `81 87 84 9F 21 00`
  - `찾았다!`: `84 91 82 9B 81 C3 21 00`
  - 두 슬롯 모두 CSV 기대 바이트와 일치하므로 TSQV 저장 잘림이 아님.
- 원인: `fonttbl`의 단일바이트 64개 항목에는 `A–Z`, `a–z`, `0–9`, 공백만 있고 `0x21(!)` 및 다른 ASCII 문장부호가 없음.

영향 범위:

| 구분 | 영향 행 | 문장부호 출현 수 |
|---|---:|---:|
| STTV | 214 | 574 |
| TSQV | 740 | 914 |
| 합계 | 954 | 1,488 |

현재 번역에서 사용 중이지만 단일바이트 폰트에 없는 문자는 다음 10종입니다.

```text
!  ?  .  ,  -  (  )  <  >  ~
```

권장 수정 전략:

1. 번역 CSV는 변경하지 않고 ASCII 문장부호 10종을 사용자 정의 2바이트 문자 매핑 대상에 추가한다.
2. 통합 글리프 목록을 `한글 850자 + ASCII 문장부호 10자 = 860자`로 구성한다.
3. `font.ttf`로 문장부호 타일도 렌더링하고 `fonttbl`에 충돌 없는 코드를 등록한다.
4. STTV와 TSQV 인코더가 `char_to_sjis`를 우선 조회해 ASCII 문장부호를 사용자 정의 2바이트 코드로 기록하게 한다.
5. 안전 타일 887개 중 860개를 사용하므로 27개가 남는지 검증한다.
6. 전체 빌드 후 1,488개 문장부호와 첫 대사를 다시 확인한다.

적용 결과:

- 문장부호 타일: 953~962, 빈 글리프 0개
